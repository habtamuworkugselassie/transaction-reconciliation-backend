# ADR-004: Upload storage is a port with a local-filesystem adapter

**Status:** accepted

## Context

Uploads must be streamed, never buffered in memory, and readable by whichever worker
claims the job. The project must run locally without paid services.

## Decision

`FileStorage` port with `LocalFileStorage`: writes to `<key>.part` and renames
atomically, keys are generated by the application (`imports/<uuid>.ndjson`), the root is
a shared Docker volume (dev) or host directory (droplet). Spring's multipart resolver is
disabled; the multipart body is read as a stream and written exactly once while being
counted, hashed and sniffed.

## Consequences

- Single write, bounded memory, partial files never visible.
- Multi-host deployments need an S3-compatible adapter behind the same port (keys are
  already opaque, so nothing else changes). Until then the API and worker must share a
  filesystem, which the compose files guarantee.
